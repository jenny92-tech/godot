# SDL2 DisplayServer for linuxbsd

A SDL2-backed `DisplayServer` for Godot 4.5+ targeting **embedded Linux handhelds**
(PortMaster ecosystem, arm64 Mali/Adreno SBCs) where the closed-source Mali
userspace driver (`libmali`) only exposes **`EGL_KHR_platform_gbm`** — not
`EGL_KHR_platform_x11` or `EGL_KHR_platform_wayland`.

On such devices, Godot's stock X11 and Wayland display drivers both fail with
`Can't get a valid initial EGL display`, because `eglGetPlatformDisplay(EGL_PLATFORM_X11_KHR, …)`
and `eglGetPlatformDisplay(EGL_PLATFORM_WAYLAND_EXT, …)` are unsupported.

This driver delegates display + GL context creation to SDL2:

```
godot main loop
  → DisplayServerSDL2::swap_buffers()
    → SDL_GL_SwapWindow()
      → SDL2 KMSDRM video driver
        → GBM buffer
          → DRM pageflip
            → panel
```

SDL2 handles all the EGL plumbing internally. Godot's GLES3 rasterizer keeps
working because all it needs is a current GL context and `eglGetProcAddress`,
both of which SDL2 provides.

## Build

Enabled with `sdl2=yes` SCons flag (default: off). Requires `libsdl2-dev` at
build time and SDL2 runtime on target.

```
scons platform=linuxbsd arch=arm64 sdl2=yes x11=no wayland=no \
      target=template_release module_mono_enabled=yes
```

## Run

Set `SDL_VIDEODRIVER=kmsdrm` to use the KMSDRM backend (preferred on handhelds).
Other valid values: `wayland`, `x11`, `fbcon`, `offscreen` (when present).

```
SDL_VIDEODRIVER=kmsdrm ./godot.linuxbsd.template_release.arm64.mono \
  --display-driver sdl2 --rendering-driver opengl3 \
  --resolution 1280x720 --main-pack mygame.pck
```

## Why this exists

Reference port: PortMaster ships `frt_4.0.4.squashfs` and `frt_4.1.3.squashfs`
which are community-built Godot 4.x SBC binaries using this exact strategy.
Source for those builds is not public; this module is a clean-room
implementation against Godot 4.5-stable, with `module_mono_enabled` support.

See:
- `display_server_sdl2.{h,cpp}` — manual impls of constructor, swap, event pump, ~27 critical methods
- `display_server_sdl2_stubs.gen.{h,cpp}` — 92 trivial stubs generated by `gen_stubs.py`
  from `servers/display_server.h` (so adding new pure virtuals upstream is a 5-second regen).

## Caveats / TODO

- Input event translation in `_process_sdl_event` only handles `SDL_QUIT` and window
  resize for the POC. `SDL_KEYDOWN/UP`, `SDL_MOUSEBUTTON*`, `SDL_MOUSEMOTION` → godot
  `InputEventKey/MouseMotion/MouseButton` mapping still needs to be filled in.
- Joystick: godot's existing `joypad_linux` (udev-based) is likely sufficient; SDL2
  `SDL_GameController*` integration could replace it if udev pathway is missing on
  some handheld distros.
- Multi-window: stubbed (handhelds are single-window full-screen by design).
- Cursor shape changes / hardware cursors: stubbed.
- IME: stubbed.
